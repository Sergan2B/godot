**Status:** Complete and locally verified

**Parent plan:** [SPRINT-3-PLAN.md](SPRINT-3-PLAN.md)

## 1. Outcome

Stage 1 freezes the storage-neutral resource identity and graph contract, then proves
that contract with an implementation-independent Godot fixture and canonical oracle.
The outputs are:

1. a reviewable `INDEX-001` draft with no ambiguous resource identity, revision,
   generation, relation, diagnostic, or query rules;
2. a deterministic fixture covering text, binary, scene-as-resource, and imported
   formats;
3. a versioned golden graph for base and mutation phases;
4. a validator that compares declared truth with Godot's resource projection without
   reading any production index implementation.

This stage does not choose the persistent storage backend, extend Bridge RPC, implement
the C++ adapter, or write the Rust index. Storage decision `D-05` remains open for
`S3-03`, but the logical contract it must implement is frozen here.

## 3. Contract decisions to freeze in `INDEX-001`

### 3.1 Source authority and identity

`INDEX-001` must include a normative decision table and canonical before/after examples
for every row below.

| Case | Contract that must be frozen |
|---|---|
| Valid `ResourceUID` | One deterministic entity ID with `persistent` scope; current path is mutable metadata |
| Missing UID | Entity ID derives from normalized `res://` path plus content generation; scope is `content_revision` and the weakness is explicit |
| UID-preserving rename | Entity ID is unchanged; old path stops resolving; one move/upsert transition updates direct and reverse views |
| UID-less rename | Remove plus upsert; no persistent-identity claim and no move inference from equal bytes |
| Delete/re-add with UID | Tombstone and inbound diagnostics are bounded; the same UID may restore the same entity identity in a later committed generation |
| Path-only missing target | Edge remains observable with `missing_dependency`; it is not converted into a stale UID |
| Unresolvable UID target | Edge remains observable with `stale_resource_uid`; no path heuristic silently rebinds it |
| UID/path disagreement | Preserve both observations, emit a deterministic diagnostic, and refuse silent rebind |
| Equal content | Two resources remain distinct; content hash is evidence about bytes, never an identity key by itself |
| Imported asset | Source `res://` resource is the entity; `.godot/imported` payload is import metadata/artifact, not a separately queryable project resource |
| Unicode/case | Normalize separators and dot segments without case folding; preserve valid Unicode spelling and diagnose non-portable collisions |
| Subresource | Explicitly deferred to `D-06`/Sprint 4; Stage 1 entity or edge data cannot imply persistent subresource identity |

For every entity ID algorithm, `INDEX-001` records the domain separator, canonical
input, algorithm/version, encoding or digest choice, and collision handling. IDs remain
opaque to MCP clients even though the producers and golden vectors must reproduce them
exactly.

Path normalization must accept only project-scoped `res://` paths, use `/` separators,
eliminate redundant `.` segments, reject `..`, absolute filesystem paths, NUL, and
root/symlink/reparse-point escape, and define trailing-slash and empty-component
behavior. The contract must distinguish a display path from the canonical comparison
key where the host filesystem requires it.

### 3.2 Logical graph

The Stage 1 logical schema contains these storage-neutral records:

- `IndexMetadata`: schema version, compatibility range, project ID, active generation,
  hash algorithm, and build state;
- `ResourceEntity`: entity ID, UID state, current path, identity scope/strength, Godot
  type, source/import marker, import state, content generation, and validity;
- `SourceDocument`: project-relative path, mtime, byte size, optional SHA-256, and
  ingest/hash status;
- `DependencyEdge`: stable edge key, source entity, target UID/path reference, optional
  resolved target, declared type, resolution status, authority, and observed resource
  revision;
- `Diagnostic`: stable code, affected entity/reference, severity, bounded safe details,
  first/last observed revision, and resolution state;
- `IngestionCheckpoint`: editor session, resource revision, project revision, index
  revision, and completeness;
- `IndexGeneration`: generation ID, parent generation, schema version, staging/active/
  quarantined state, creation reason, and activation metadata.

Direct dependency edges are authoritative observations from Godot. Reverse owners are a
derived index over the same committed edge set and revision; they are not a second source
of truth. Cycles are valid. Recursive traversal is not part of the Stage 1 or Sprint 3
query contract.

### 3.3 Revision, generation, and transition rules

`INDEX-001` must define, without backend terminology:

- the scope and monotonicity of `resource_revision`, `project_revision`,
  `index_revision`, `generation_id`, and `content_generation`;
- which values survive editor/sidecar restart and which are session-scoped;
- the exact precondition for applying an incremental batch;
- atomic visibility of entity, document, edge, reverse-edge, diagnostic, checkpoint,
  and revision changes;
- full snapshot activation, cancellation, journal gap, corruption quarantine, and
  compatible reopen state machines;
- tombstone retention and the point at which resolved diagnostics disappear;
- deterministic ordering and deduplication when Godot reports the same dependency more
  than once.

Mutation golden files assert relationships such as “same entity ID”, “index revision
advances once”, and “full rebuild count unchanged”. They do not hard-code
session-dependent counter values.

### 3.4 Query semantics

The storage-neutral query contract freezes:

- lookup by entity ID, UID, or normalized `res://` path and the ambiguity/error rules;
- direct dependencies and direct reverse owners only;
- deterministic ordering by canonical path, then UID/entity ID as tie-breakers;
- hard result limits, pagination, and opaque cursors bound to project ID, query shape,
  and index revision;
- partial results and structured diagnostics for missing/stale targets;
- stale cursor, stale index, invalid path, unavailable capability, and limit errors;
- the rule that queries see one active generation and never staging data.

The future MCP tools may shape this result, but they may not weaken or reinterpret the
graph semantics fixed here.

### 3.5 Versioning and migration boundary

Stage 1 freezes the logical compatibility policy while leaving backend-specific
migration mechanics to `S3-03`/`S3-06`:

- each stored generation declares a semantic schema version and the reader/writer
  compatibility range that created it;
- compatible additive changes have an explicit defaulting rule; a reader cannot infer
  a default that changes identity, edge resolution, or diagnostic meaning;
- incompatible versions are never queried as current and require a staged migration or
  clean rebuild;
- migration writes a new staging generation, is restartable/idempotent, and cannot
  mutate or activate over the last valid generation before validation succeeds;
- cancellation, crash, or failed validation preserves the prior active generation and
  records a bounded recovery reason;
- `D-05` later chooses physical storage and migration implementation without changing
  these observable guarantees.

## 4. Golden fixture design

### 4.1 Base topology

The fixture uses built-in Godot resource types so test truth does not depend on project
scripts or third-party addons. Logical names below are oracle IDs, not production entity
IDs.

| Topology | Required logical shape |
|---|---|
| Chain | `chain_root -> chain_mid -> shared_leaf` |
| Fan-out | `fan_out -> shared_leaf` and `fan_out -> unique_leaf` |
| Fan-in | `fan_in_a -> shared_leaf` and `fan_in_b -> shared_leaf` |
| Cycle | `cycle_a -> cycle_b` and `cycle_b -> cycle_a` |
| Orphan | `orphan` has no incoming or outgoing edges |
| Missing path | `missing_owner -> res://missing/not_created.tres` |
| Stale UID | `stale_uid_owner -> <valid but unresolvable fixture UID>` |
| Equal bytes | `twin_a` and `twin_b` have equal content but distinct identities |
| Path boundary | One valid resource path contains spaces and non-ASCII Unicode |

The format matrix must include `.tres`, `.res`, `.tscn`, `.scn`, and one imported
source asset with valid import metadata. Scenes are treated only as Resource entities;
the oracle contains no node, inheritance, instance, signal, or script-symbol semantics.

### 4.2 Oracle format

`golden-resource-graph.schema.json` uses JSON Schema Draft 2020-12. Every golden phase
contains:

- `schema_version`, `fixture_version`, `phase`, and required Godot compatibility;
- canonical resources with oracle ID, exact expected entity ID, UID state, normalized
  path, format, Godot type, identity scope/strength, import state, and hash assertion;
- canonical declared dependency edges and resolution status;
- expected diagnostics;
- expected direct query results; reverse results are derived from the direct edge set by
  the independent validator so two hand-maintained truths cannot disagree;
- transition assertions relative to the preceding phase;
- explicit exclusions proving that `.godot/`, oracle files, and absolute paths are not
  indexed or emitted.

`hash_assertion` is `exact_sha256` for committed deterministic source bytes and
`runtime_sha256` for Godot-generated binary resource files. Imported sources use their
committed source bytes; internal `.godot/imported` payloads remain non-queryable import
metadata. In every case the validator later compares the observed index hash against
actual bounded source/resource bytes; semantic truth never assumes that equal hashes
imply equal identity.

### 4.3 Mutation phases

Each phase starts from a clean materialized baseline and is applied by the fixture
driver, not by ad-hoc shell edits.

| Phase | Operation | Required assertion |
|---|---|---|
| `base` | Restore and import the canonical project | Full resource/edge/diagnostic truth matches |
| `rename_uid` | Rename a UID-backed resource and update its owning reference | Same entity ID; paths and reverse owners change; no full rebuild expectation |
| `rename_uidless` | Rename a UID-less resource | Old identity removed; new content-revision identity inserted |
| `delete` | Delete a referenced resource | Target/tombstone policy and inbound diagnostic match |
| `re_add` | Restore the deleted resource with its fixture UID | Resolution returns deterministically and stale diagnostic clears per contract |
| `reimport` | Change imported source bytes and run import | Resource identity stays stable; import/hash/content generation changes |
| `content_edit` | Edit a non-renamed resource | Identity behavior and hash/content generation follow UID strength |
| `journal_gap` | Omit one declared mutation event in the synthetic transition trace | Expected result is invalidation/full snapshot, never a guessed delta |

The fixture driver supports deterministic `restore`, `apply`, `probe`, and `validate`
operations. Running `restore` twice must yield the same tracked files and semantic
oracle. Each mutation must be reversible by `restore` without relying on Git cleanup.

## 6. Planned command surface and verification

The stage implementation should expose one cross-platform Python entry point rather than
platform-specific shell mutations:

```text
python3 tests/codex/resource_graph_fixture.py restore --phase base
python3 tests/codex/resource_graph_fixture.py apply --phase rename_uid
python3 tests/codex/resource_graph_fixture.py probe --godot-bin <editor>
python3 tests/codex/resource_graph_fixture.py validate --all-phases
python3 -m unittest tests.codex.test_resource_graph_contract
```

The final command names may be adjusted during implementation, but the following checks
are mandatory:

- strict JSON parsing and Draft 2020-12 validation;
- exact canonical resource, edge, diagnostic, and query diff;
- fixture restore idempotence and tracked-file cleanliness;
- Godot headless editor import/open and ResourceUID/dependency projection;
- valid UID and fallback entity-ID golden vectors;
- Unicode path, traversal/absolute-path negatives, duplicate UID/path conflict, stale
  UID, missing target, and unsupported subresource-identity negatives;
- no production index module imported by the fixture validator;
- no absolute host path, `.godot/imported` payload path, token, or source payload in
  golden results or ordinary logs.

## 8. Exit gate

Stage 1 is complete only when all ten acceptance rows have direct evidence and:

- `INDEX-001` is marked “contract frozen; `D-05` pending” rather than accepted as a
  finished storage decision;
- the oracle schema, base graph, mutation graphs, identity vectors, and fixture driver
  are committed together so none can drift independently;
- the enabled Godot build opens/imports the restored fixture and the Godot API probe
  exactly matches the oracle's overlapping UID/path/type/import/dependency facts;
- the validator passes from a clean restore twice and leaves no tracked changes;
- the parent `S3-01`/`S3-02` rows and this matrix are updated with actual evidence;
- unresolved backend, Bridge RPC, or platform-live work remains assigned to `S3-03`
  through `S3-10`, not relabeled as completed by this contract gate.

Passing this gate authorizes the storage spike and protocol schema implementation. It
does not complete Sprint 3.
